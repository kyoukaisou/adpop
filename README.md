# ADPOP

**ライセンスはディレクトリで分かれています**: `packages/embed/` = **MIT** / それ以外 = **AGPL-3.0**。
詳細は **[LICENSING.md](./LICENSING.md)**(ルートの `LICENSE` は AGPL-3.0 の全文だけを置いています)。

**LP に `<script>` を1行貼るだけで、離脱しかけた訪問者にポップを出す**ツール。

いま LP から出ていく人はそのまま消えるだけで、再訪も再提案もできない。ADPOP を入れると
**離脱の瞬間に「もう1回だけ提案する枠」**が生まれ、**その枠の効き目(表示・クリック・トリガ別)が
数字で見える**ようになる。

> ⚠ **いまは配信までです**(PR2)。**管理画面がまだ無い**ので、サイトとポップを作るには
> SQL を直接書く必要があります。何が入っていて何が入っていないかは、下の
> 「いまできること」と「入っていないもの」を見てください。

## ライセンス(ディレクトリで分かれている)

| 場所 | ライセンス |
|---|---|
| `packages/embed/`(npm 名 `adpop-js`。他人の LP に読み込まれる側) | **MIT** |
| それ以外すべて(サーバー・管理画面) | **AGPL-3.0** |

理由と、分割を機械で効かせている場所は **[LICENSING.md](./LICENSING.md)** に書いてあります。

## v1 の範囲

| 入れる | 入れない |
|---|---|
| 埋め込みタグ(`<script>` 1行)+ 配信エンドポイント | 入力フォーム / リード獲得(**個人情報を1件も集めない**) |
| 離脱トリガ6種(戻る・スクロール・無操作・滞在・タブ切替・exit intent) | AI の自由回答チャット |
| ポップの型2種(テキスト+ボタン / 画像・GIF) | 任意 HTML・CSS・JS の入力(XSS の入口を作らない) |
| 頻度制御(N日出さない / セッション内1回 / CV 後は出さない) | ASP パラメータの引き継ぎ |
| A/B テスト(バリアント別の数値) | A/B の自動勝者選定 |
| 数値(表示・クリック・閉じる・トリガ別・バリアント別・端末別) | 複数ユーザー・チーム権限 |
| CV 計測タグ(任意・自社サンクスページ用) | 課金・ホスティング版 |
| 管理画面(単一管理者) | チャットボット型のポップ(🕐 v1.1) |

⚠ **成約(ASP)の数字は取りません。** ASP 側にあり、こちらからは観測できないためです。

## いまできること(PR2 までの範囲)

- ライセンスの分割(MIT / AGPL-3.0)と、それを守る CI の検査
- **データモデル**(サイト / ポップ / トリガ設定 / バリアント / チャットボットのノード / イベント)の
  マイグレーションと **RLS + 権限**
- **配信エンドポイント** `GET /api/v1/config` —— サイトキー + `Origin` から、いま有効なポップの設定を返す
- **イベント投入** `POST /api/v1/events` —— 発火・抑制・表示・クリック・閉じるを受ける
- **埋め込みスクリプト**(タグ1本 → 設定取得 → 離脱の検知 → ポップの表示)
- CI(lint・typecheck・test・サイズ上限・依存の向き・**実物の Supabase で権限を実測**)

### 埋め込み方(いまの形)

```html
<script async src="https://<配信ホスト>/embed/t.js" data-adpop-site="<サイトキー>"></script>
```

- **配信ホストはタグの `src` から読みます。**コードに直書きしていないので、
  ドメインを変えたらタグを貼り替えるだけで移せます。
- ⚠ サイトキーは **HTML に出る公開値**です。秘密ではありません。守っているのは
  **許可ドメイン**(`sites.allowed_origins`)で、**登録していない Origin には設定を返しません**。
- `?adpop_preview=1` を付けると**頻度制御を無視して出ます**。⚠ このときのイベントは**1件も送りません**。

### PR2 に入っていないもの(意図して入れていない)

| 入れていないもの | いつ | 補足 |
|---|---|---|
| **管理画面** | PR3 | いまサイト・ポップ・バリアントを作るには **SQL を直接書く**必要があります |
| **トリガ ②スクロール ③無操作 ④滞在 ⑤タブ切替** | PR4 | **実装したのは ①戻る と ⑥exit intent の2つだけ**。⚠ サーバーは有効なトリガを6種すべて返しますが、**埋め込みスクリプトは知らない種類を黙って無視します**(= 管理画面で ON にしても PR4 までは何も起きません) |
| **ポップの型 B(画像 / GIF)** | PR4 | いまは**テキスト + ボタン**だけ |
| **A/B の割り当て** | PR5 | 重みは配信の応答に載っていますが、**1ミリも使っていません**。出るのは**先頭のバリアント**です |
| **CV 計測タグ(`conversion`)** | PR6 | 投入エンドポイントは `conversion` を**受け付けません**(別の入口になるため) |
| 🔴 **レート制限** | PR4 以降 | **入っていません。** イベント投入は `Origin` と サイトキー の確認と、本文 4KB の上限だけで守っています |
| **設定 JSON の CDN キャッシュ** | 未定 | 応答が**サイトキー × Origin の認可の結果**なので、無効化の手順を決めるまで入れません(いまは `no-store`) |
| **プレビュー(preflight)対応** | 未定 | 埋め込みスクリプトは**単純リクエストしか送らない**(`text/plain`)ので preflight は起きません。`OPTIONS` は実装していません |

## 動かし方(開発)

前提: Node.js 24 / Docker(ローカルの Supabase 用)

```bash
npm install
cp .env.example .env.local     # ⚠ 値は .env.local にだけ書く(.env* は追跡しない)

# ローカルの Supabase(クラウドのプロジェクトは作りません)
npx supabase start             # ポートは 5452x(他プロダクトのローカルと衝突しない値にしてある)
npx supabase db reset          # supabase/migrations/*.sql を順に適用する

npm run lint
npm run typecheck
npm test                       # ⚠ Docker も Supabase も要らない(PGlite にマイグレーションを流す)
npm run build:embed            # 埋め込みスクリプトを packages/embed/dist と public/embed へ書き出す
npm run check:bundle-size
npm run check:embed-independence

# ローカルの Supabase が起動している間だけ動く(実物の PostgREST に当たる)
npm run check:postgrest
```

⚠ **`npm test` はローカルの Supabase を使いません。** マイグレーションを **PGlite**(WASM の PostgreSQL)へ
通しで流し、**権限と RLS の実効値をその場で測ります**。

🔴 **ただし PGlite 側の「Supabase の既定privilege」は手書きの再現です。**
再現が実物とずれたら、検査は**ずれた前提を測り続けます**。
そのため **CI に実物の Supabase を起動するジョブ**があり、
`anon` キーと `service_role` キーで6表を叩いて **HTTP と SQLSTATE の両方**を突き合わせます
(`npm run check:postgrest`)。⚠ このジョブが見ているのは**未ログインの経路だけ**で、
**ログイン後(authenticated)の経路は実物では1度も通していません**(ログインする画面が PR3 のため)。

同じジョブが**逆向き**も測ります —— **配信の関数2本が `anon` から呼べること**。
🔴 配り漏れると**配信だけが静かに止まります**(LP は無傷のままポップが出なくなるので、
誰も気づきません)。「届かないこと」だけを測っていると、この故障を1つも検出できません。

## 外部送信する情報の一覧(電気通信事業法・外部送信規律)

**このタグが外部送信する情報**は次のとおりです(PR2 時点。**そのまま転記できる形**で置いています)。

| 項目 | 内容 |
|---|---|
| **送信先** | タグの `src` に書いた配信ホスト(**自前ホストなら、その運営者自身のサーバー**) |
| **送信される情報** | 匿名ID(`localStorage` 由来の32桁の16進)/ **ページ URL(スキーム + ホスト + パスのみ)** / イベントの種類(発火・抑制・表示・クリック・閉じる)/ トリガ種別 / **端末種別(スマホ・PC の2値)** / 閉じ方(ボタン・背景・Esc)/ 発生時刻 / サイトキー・ポップとバリアントの公開用の識別子 |
| **送信されない情報** | 氏名・メールアドレス・電話番号 / **URL のクエリ文字列とフラグメント**(送る前にも、保存する前にも落とします)/ **IP アドレスの保存** / 生の User-Agent / サードパーティ Cookie |
| **利用目的** | ポップの表示制御と効果測定 |
| **送信を止める方法** | タグを外すこと(⚠ オプトアウト UI はありません) |

⚠ 埋め込み先の運営者が規律の対象事業者に当たるかは、その人の事業内容で決まります。
**ADPOP は「対象です / 対象外です」の判定をしません。**

## 自前ホスト

**v1 の時点では手順を用意していません**(PR6)。いまの構成は Next.js + Supabase + Cloudflare R2 です。
⚠ Supabase に強く食い込まない形(RLS と Auth への依存を、後で剥がせる程度に抑える)を実装制約にしています。

## 数字の読み方(先に断っておくこと)

**イベントは埋め込み先のブラウザから送られてくるので、誰でも偽造できます。**
数字は「自分の LP の傾向を見る」用途に限り、**第三者への実績提示には使わないでください**。

## 既知の限界

- **頻度制御は埋め込み先ドメインの `localStorage`** に保存します。
  localStorage が使えない / 消される環境では**抑制が効きません**(Cookie にも第三者にも逃がしません)。
- 訪問者の識別は**匿名IDのみ**。サーバーに氏名・メール・電話は存在せず、
  **IP アドレスは保存せず**、User-Agent は「スマホ / PC」の2値に落とします。
- **オプトアウト UI はありません**(止める方法はタグを外すこと)。
- 🔴 **イベント投入にレート制限がありません**(PR4 以降)。守っているのは `Origin` の照合と
  サイトキーの存在確認、本文 4KB の上限だけです。
- **①戻るトリガは、埋め込み先の履歴を触ります**(`history.pushState` を1枚挟みます)。
  自前で `history` を使う SPA では干渉しえます。⚠ **このトリガだけ個別に OFF にできます**
  (OFF なら `history` に1ミリも触りません)。
- **匿名IDは、`crypto` が使えない環境では `Math.random` で作ります。**暗号的ではありません
  (頻度制御のための識別子で、秘密でも認証でもないため)。
- **端末の2値は `(pointer: coarse)`**、それが無ければ `navigator.maxTouchPoints` で決めます。
  ⚠ どちらも無い古い環境は「PC」と数えます。
