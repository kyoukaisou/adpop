# ADPOP

**ライセンスはディレクトリで分かれています**: `packages/embed/` = **MIT** / それ以外 = **AGPL-3.0**。
詳細は **[LICENSING.md](./LICENSING.md)**(ルートの `LICENSE` は AGPL-3.0 の全文だけを置いています)。

**LP に `<script>` を1行貼るだけで、離脱しかけた訪問者にポップを出す**ツール。

いま LP から出ていく人はそのまま消えるだけで、再訪も再提案もできない。ADPOP を入れると
**離脱の瞬間に「もう1回だけ提案する枠」**が生まれ、**その枠の効き目(表示・クリック・トリガ別)が
数字で見える**ようになる。

> ⚠ **いまは配信までです**。**管理画面がまだ無い**ので(PR3b)、サイトとポップを作るには
> データ層の関数を呼ぶか SQL を直接書く必要があります。
> 土台は **Cloudflare(Workers + D1 + R2)** です(2026-09-30 に Supabase から移しました)。

## ライセンス(ディレクトリで分かれている)

| 場所 | ライセンス |
|---|---|
| `packages/embed/`(npm 名 `adpop-js`。他人の LP に読み込まれる側) | **MIT** |

理由と、分割を機械で効かせている場所は **[LICENSING.md](./LICENSING.md)** に書いてあります。

| 入れる | 入れない |

## いまできること

- ライセンスの分割(MIT / AGPL-3.0)と、それを守る CI の検査
- **データモデル**(所有者 / サイト / 許可ドメイン / ポップ / トリガ設定 / パターン / チャットボットのノード / イベント)
  —— **Cloudflare D1**(`db/migrations/`)
- **配信の Worker**(`src/delivery/worker.ts`・設定は `wrangler.delivery.jsonc`)
  - `GET /api/v1/config` —— サイトキー + `Origin` から、いま有効なポップの設定を返す
  - `POST /api/v1/events` —— 発火・抑制・表示・クリック・閉じるを受ける
  - `/embed/*` —— 埋め込みスクリプト(静的配信)
- **管理画面が使うデータ層**(`src/lib/data/admin.ts`。画面は PR3b)
- **埋め込みスクリプト**(タグ1本 → 設定取得 → 離脱の検知 → ポップの表示)

### 守りの置き場所(D1 には RLS も GRANT も無い)

| 守り | どこで | 検査 |
|---|---|---|
| 未認証の入口から表へ届かない | D1 はネットワークに API を出さない。届くのは**配信の Worker のバインド**と、Cloudflare アカウントの API トークン(wrangler / D1 の HTTP API)だけ | `tests/d1-worker-runtime.test.ts`(配信の口以外は 404) |
| 所有者の分離 | データ層の全関数が `ownerId` を取り、SQL に `owner_id = ?` を入れる。挿入は複合外部キー `(親の id, owner_id)` が他人の親を断る | `tests/d1-owner-isolation.test.ts`(公開関数を列挙して全部を他人として撃つ) |
| D1 に触る場所 | `src/lib/data/` だけ | `tests/d1-access-boundary.test.ts`(TypeScript の型で呼び出しを探す) |
| 件数の上限(サイト 20 / ポップ 50 / パターン 5) | D1 の行トリガ(`RAISE(ABORT)`)。アーカイブ済みは数えず、戻すときに数える | `tests/d1-limits.test.ts` |
| 1サイトに稼働中は1つ | 部分一意索引 | `tests/d1-schema.test.ts` |
| イベントの形・階層の一致・重複排除 | CHECK / 複合外部キー / 一意索引 | `tests/d1-schema.test.ts` |
| 形の完全な判定(Origin・https・`page_url`) | `src/lib/data/shapes.ts` | `tests/d1-delivery.test.ts` |

### D1 に移して弱くなった守り(代償)

- 🔴 **DB が最後の砦ではなくなりました。** 所有者の分離はデータ層のコードが持つので、
  **その誤り1つで他人の行に届きます**(旧版は RLS が止めました)。検査は全関数を撃ちますが、
  **検査に無い書き方**(`any` に落とした D1 の呼び出しなど)は見えません。v1 は管理者1人です。
- 🔴 **形の検査が DB に残るのは GLOB / LIKE で書ける範囲だけです**(SQLite に正規表現が無い)。
  `https://localhost` のようなドットの無いホストは、**DB を直接触られると**許可ドメインとして入ります
  (配信の口は入口で `isOrigin` を通すので、そこからは入りません)。
- 🔴 **Cloudflare の API トークンに D1 の権限があれば、全データを読み書きできます。**
  旧版の「専用ロールで届く範囲を関門で数える」に当たるものはありません。**トークンの範囲を絞るのは運用**です。
- ⚠ **本文 4KB の上限は Worker の中の1か所だけ**になりました(旧版は DB の関数にも置いていました)。
  旧版が2か所に置いたのは PostgREST から関数を直接叩けたためで、**D1 にはその経路がありません**。
- ⚠ 同時実行: 上限の判定は「D1 は1つのデータベースのクエリを1つずつ処理する」
  (Cloudflare の D1 limits の文書)に乗っています。**2つの要求を本当に並べて撃つ検査はありません**
  (ローカルでは並びを保証できないため)。

### 埋め込み方(いまの形)

```html
<script async src="https://<配信ホスト>/embed/t.js" data-adpop-site="<サイトキー>"></script>
```

- **配信ホストはタグの `src` から読みます。**コードに直書きしていないので、
  ドメインを変えたらタグを貼り替えるだけで移せます。
- ⚠ サイトキーは **HTML に出る公開値**です。秘密ではありません。守っているのは
  **許可ドメイン**(`site_allowed_origins`)で、**登録していない Origin には設定を返しません**。
- `?adpop_preview=1` を付けると**頻度制御を無視して出ます**。⚠ このときのイベントは**1件も送りません**。

| **トリガ ①戻る ②スクロール ③無操作 ④滞在 ⑤タブ切替** | PR4 | **実装しているのは ⑥exit intent の1つだけ**。⚠ サーバーは有効なトリガをすべて返しますが、**埋め込みスクリプトは知らない種類を黙って無視します** |
| **ポップの型 B(画像 / GIF)** | PR4 | いまは**テキスト + ボタン**だけ |
| **A/B の割り当て** | PR5 | 重みは配信の応答に載っていますが、**1ミリも使っていません**。出るのは**先頭のバリアント**です |

## 動かし方(開発)

前提: Node.js 24。**Cloudflare のアカウントは要りません**(全部ローカルの wrangler / workerd で動きます)。

```bash
npm install
npm run lint
npm run typecheck
npm test                          # D1 の型紙を `wrangler d1 migrations apply --local` で作ってから走る
npm run check:bundle-size
npm run check:embed-independence
npm run build

# 配信の Worker をローカルで起動する(http://localhost:8787)
npm run delivery:migrate:local    # ローカルの D1 にスキーマを当てる(.wrangler/state)
npm run delivery:dev              # 埋め込みスクリプトを束ねてから wrangler dev
```

⚠ `npm test` が使う D1 は、**本番と同じ `wrangler d1 migrations apply`** で作った型紙の複写です
(`tests/setup/d1-template.ts`)。SQL を自前で文に分けて流すことはしていません。

## 外部送信する情報の一覧(電気通信事業法・外部送信規律)

**このタグが外部送信する情報**は次のとおりです(PR2 時点。**そのまま転記できる形**で置いています)。

| 項目 | 内容 |
|---|---|
| **送信先** | タグの `src` に書いた配信ホスト(**自前ホストなら、その運営者自身のサーバー**) |
| **送信される情報** | 匿名ID(`localStorage` 由来の32桁の16進)/ **ページ URL(スキーム + ホスト + パスのみ)** / イベントの種類(発火・抑制・表示・クリック・閉じる)/ トリガ種別 / **端末種別(スマホ・PC の2値)** / 閉じ方(ボタン・背景・Esc)/ 発生時刻 / サイトキー・ポップとバリアントの公開用の識別子 |
| **送信されない情報** | **URL のクエリ文字列とフラグメント**(送る前にも、保存する前にも落とします)/ **IP アドレスの保存** / 生の User-Agent / サードパーティ Cookie / 入力フォームは持っていないので、訪問者が入力した値 |
| 🔴 **送信されうる情報(注意)** | **ページ URL のパスに氏名やメールアドレスが含まれている場合、それは送信されます。** ADPOP が落とすのは**クエリ文字列とフラグメントだけ**で、パスは残します(`/thanks/taro@example.com` のような URL 設計をしている LP では、タグを貼る前に URL を見直してください)。⚠ ただし `user@host` の形(`https://taro@example.com/…`)は**保存を断ります** |
| **利用目的** | ポップの表示制御と効果測定 |
| **送信を止める方法** | タグを外すこと(⚠ オプトアウト UI はありません) |

⚠ 埋め込み先の運営者が規律の対象事業者に当たるかは、その人の事業内容で決まります。
**ADPOP は「対象です / 対象外です」の判定をしません。**

## 数字の読み方(先に断っておくこと)

**イベントは埋め込み先のブラウザから送られてくるので、誰でも偽造できます。**
数字は「自分の LP の傾向を見る」用途に限り、**第三者への実績提示には使わないでください**。

## 既知の限界

- **頻度制御は埋め込み先ドメインの `localStorage`** に保存します。
  localStorage が使えない / 消される環境では**抑制が効きません**(Cookie にも第三者にも逃がしません)。
- 訪問者の識別は**匿名IDのみ**。**IP アドレスは保存せず**、User-Agent は「スマホ / PC」の2値に落とします。
  ⚠ **「氏名・メール・電話を送らない」とは言い切れません** —— それらが**ページ URL のパスに
  含まれていれば送信されます**(落とすのはクエリ文字列とフラグメントだけ)。上の表を見てください。
- **オプトアウト UI はありません**(止める方法はタグを外すこと)。
- 🔴 **イベント投入にレート制限がありません**(PR4 以降)。守っているのは `Origin` の照合と
  サイトキーの存在確認、本文 4KB の上限だけです。
- **①戻るトリガはまだ実装していません**(PR4)。いまの埋め込みスクリプトは `history` に触りません。
- **匿名IDは、`crypto` が使えない環境では `Math.random` で作ります。**暗号的ではありません
  (頻度制御のための識別子で、秘密でも認証でもないため)。
- **端末の2値は `(pointer: coarse)`**、それが無ければ `navigator.maxTouchPoints` で決めます。
  ⚠ どちらも無い古い環境は「PC」と数えます。
- 🔴 **Origin の偽造は防げません。** ブラウザは本物の Origin を送るので、
  「他人が自分の LP にタグを貼った」場合は止まります。**curl に対しては何も守っていません。**
- **①戻るトリガは、出さないと決めたときに `history.back()` で「戻る」を通し直します。**
  ⚠ LP が履歴の最初のページ(直接訪問)なら、その `history.back()` は何も起こしません。
  ⚠ **本体の取得に失敗したとき**(CDN 障害・CSP・広告ブロッカー)も同じく通し直します ——
  **ポップが出ないのに操作だけ奪う、をしないため**。
