# ADPOP

**ライセンスはディレクトリで分かれています**: `packages/embed/` = **MIT** / それ以外 = **AGPL-3.0**。
詳細は **[LICENSING.md](./LICENSING.md)**(ルートの `LICENSE` は AGPL-3.0 の全文だけを置いています)。

**LP に `<script>` を1行貼るだけで、離脱しかけた訪問者にポップを出す**ツール。

いま LP から出ていく人はそのまま消えるだけで、再訪も再提案もできない。ADPOP を入れると
**離脱の瞬間に「もう1回だけ提案する枠」**が生まれ、**その枠の効き目(表示・クリック・トリガ別)が
数字で見える**ようになる。

> ⚠ **いまは配信までです**(PR2)。**管理画面がまだ無い**ので、サイトとポップを作るには
> SQL を直接書く必要があります。何が入っていて何が入っていないかは、下の
> 「いまできること」と「入っていないもの」を見てください。

## ライセンス(ディレクトリで分かれている)

| 場所 | ライセンス |
|---|---|
| `packages/embed/`(npm 名 `adpop-js`。他人の LP に読み込まれる側) | **MIT** |

理由と、分割を機械で効かせている場所は **[LICENSING.md](./LICENSING.md)** に書いてあります。

## いまできること(PR2 までの範囲)

- ライセンスの分割(MIT / AGPL-3.0)と、それを守る CI の検査
- **データモデル**(サイト / ポップ / トリガ設定 / バリアント / チャットボットのノード / イベント)の
  マイグレーションと **RLS + 権限**
- **配信エンドポイント** `GET /api/v1/config` —— サイトキー + `Origin` から、いま有効なポップの設定を返す
- **イベント投入** `POST /api/v1/events` —— 発火・抑制・表示・クリック・閉じるを受ける
- **埋め込みスクリプト**(タグ1本 → 設定取得 → 離脱の検知 → ポップの表示)
- CI(lint・typecheck・test・サイズ上限・依存の向き・**実物の Supabase で権限を実測**)

### 配信エンドポイントの入口は1つ

**設定の取得もイベントの投入も、Next.js のルートが DB へ直接つないで行います。**
Supabase の Data API(PostgREST)は**経路に入っていません** ——
`anon` も `service_role` も、業務テーブルにも配信の関数にも権限を1つも持ちません。

🔴 これは「強い鍵を使う」ためではなく、**守り(本文の上限・将来のレート制限)を
1か所に集めるため**です。使う資格は **専用の Postgres ロール `adpop_delivery` 1つ**です。

### 接続文字列が漏れたら何ができるか

> 🔴 **この関門が数える権限の種別の範囲では、配信の関数2本を呼べるだけ**です。
> ⚠ **「それ以外は何もできない」とは書きません** —— 下に挙げた種別は**数えていない**からです。

**この関門が数える権限の種別**(これだけ):
表・ビュー(8種・列単位を含む)/ 連番(3種)/ 関数の `EXECUTE` /
スキーマの `USAGE`・`CREATE` / データベースの `CONNECT`・`TEMPORARY`・`CREATE` /
ロールのメンバー関係 / ロールの属性(SUPERUSER・CREATEROLE・CREATEDB・BYPASSRLS・REPLICATION) /
ロールの既定 GUC(`statement_timeout`)。

🔴 **PostgreSQL の権限種別は、これで全部ではありません。** 数えていないもの:
**型 / ドメインの `USAGE`**、**言語の `USAGE`**、**テーブル空間の `CREATE`**、
**FDW / 外部サーバーの `USAGE`**、**ラージオブジェクト**、**パラメータ(`ALTER SYSTEM`)**。
⚠ **PUBLIC が既に持っているものも数えていません**(全員が持つ地の権限で、このロール固有ではないため)。
実測では **PUBLIC が実行できる非システム関数が 101 本**あります。
これらは Supabase の拡張が持つもので、**剥がすとプラットフォームが壊れる**ので剥がしていません。

🔴 **DB の外はもっと数えていません**: TLS の設定 / Supavisor(pooler)の設定 /
`pg_hba.conf` / ネットワーク到達性。**マイグレーションからは測れません。**

**残る力**(数えた範囲の中でも防げないこと): サイトキーと許可 Origin を知っていれば、
**イベントを好きなだけ入れられます**(要件書 §4-7「イベントは誰でも偽造できる」の範囲。
レート制限は PR4)。

<details><summary>⚠ なぜ「2関数だけ」と言い切るのをやめたか(3巡かけて分かったこと)</summary>

PR2 の途中で「この資格で届くのは**関数2本ちょうど**」と2度書き、2度とも覆りました。

| 版 | 書いたこと | 実際 |
|---|---|---|
| 1回目 | `service_role` の鍵で届くのは2本だけ | **測っていたのは `/rest/v1` の `public` だけ**。鍵は **Auth Admin API と Storage** にも通り、利用者を消すと cascade で配下データが全部消えた |
| 2回目 | 専用ロールの権限を**全スキーマで数え上げた** | **数え上げを1つ足すたびに、数えていないものが1つ出た**(型・言語・テーブル空間・FDW・ラージオブジェクト・パラメータ・データベース権限・PUBLIC 由来の基礎権限…) |

→ **やめたのは「数え上げ」ではなく「全部数えたという言い方」**です。
いまは **数える種別を名指しし、数えない種別も名指し**しています。
**閉められるものは閉め**(データベースの `TEMPORARY` / `CREATE` を PUBLIC から revoke)、
**閉めた結果を関門で測り**、**閉められないものは「閉めていない」と書いて**います。

⚠ **`CONNECT` は PUBLIC から外していません。** 外すと**このデータベースの全ロールが繋げなくなり**、
後から Supabase が作るロールも巻き添えになります。しかも**買えるものがありません** ——
攻撃者は接続文字列(= パスワード)を持っている前提なので、`CONNECT` の有無は何も守らないからです。
</details>

### 時間の上限として言えること

**クライアント側で保証しているのは、接続の待ち時間(5秒)だけ**です。
**文の実行時間の上限は、ロールの既定(`statement_timeout = 5s`)に置いてあります。**

🔴 実測(2026-09-11)でここに落ち着きました:
- **関数単位の `SET statement_timeout` は効きません** —— 300ms を設定した関数の中で
  2秒の `pg_sleep` が**完走しました**(タイマーは最上位の文の開始時に張られ、途中で変えても張り直されない)
- **ロールの既定は効きます** —— 同じ sleep が `canceling statement due to statement timeout` で落ちました
- **クライアントが渡す起動時パラメータは当てにできません** —— transaction pooler では
  セッションが使い回されるので、渡した設定が残る保証がありません

### 接続の TLS

`ADPOP_DATABASE_URL` への接続は **TLS を必須**にしています(`ssl: "require"`)。
⚠ 降ろせるのは **①ホストがループバック(`localhost` / `127.0.0.1` / `::1`)で、
かつ ②URL に `sslmode=disable` と明示したとき**だけです。
**本番のホストでは `sslmode=disable` と書いても降りません。**
(ローカルの Supabase は `ssl = off` で動いているため、開発と CI にだけ逃げ道を用意しています。)

<details><summary>⚠ なぜ Supabase の <code>service_role</code> の鍵をやめたか(実測で判断が覆った)</summary>

PR2 の途中まではサーバーが `service_role` の鍵で PostgREST を呼び、
「**この鍵で届くのは関数2本だけ**」と書いていました。**その主張は測っていない範囲を含んでいました。**

| 測っていたもの | 実際 |
|---|---|
| `/rest/v1` の `public` スキーマだけ | `service_role` の鍵は **Auth Admin API と Storage API にも通る** |

実測(ローカルの本物のスタック):
`POST /auth/v1/admin/users` → anon **403** / service_role **200(利用者が作られる)**。
`DELETE` も通り、`sites.owner_id` の `on delete cascade` で
**サイト・ポップ・バリアントが全部消えました**(1/1/1 → **0/0/0**)。

→ **PostgREST を経路から外し**、資格を Postgres のロール1つにしました。
**Auth も Storage も経路に存在しない**ので、この型の穴が構造ごと消えます。
</details>

⚠ **`Origin` の偽造は防げません。** `Origin` が守るのは「他人が自分の LP にタグを貼った」場合だけで、
`curl` に対しては何も守っていません(要件書 §4-7 の「イベントは誰でも偽造できる」と同じ話)。

### 配信ロールのパスワードを設定する(自前ホスト)

マイグレーションはロールを**作るだけ**で、**パスワードは設定しません**
(リポジトリに秘密を入れない・本番へ同じ値を流さないため)。設定するまで接続できません。

```sql
alter role adpop_delivery password '<運用側で決めた値>';
```

`ADPOP_DATABASE_URL` にそのユーザーで接続する URL を入れてください。
⚠ 本番は Supabase の **transaction pooler**(6543)に繋ぎます。

```bash
# 本番(TLS は必須。sslmode は書かなくてよい)
ADPOP_DATABASE_URL=postgresql://adpop_delivery:<パスワード>@<pooler のホスト>:6543/postgres

# ローカル(⚠ ローカルの Supabase は ssl = off なので、明示的に降ろす必要がある)
ADPOP_DATABASE_URL=postgresql://adpop_delivery:<パスワード>@127.0.0.1:54522/postgres?sslmode=disable
```

🔴 **`sslmode=disable` が効くのはループバック宛てだけ**です。本番のホストに書いても**降りません**
(実測: ローカルで `sslmode` を書かずに起動すると、配信は `502` になります)。

### 埋め込み方(いまの形)

```html
<script async src="https://<配信ホスト>/embed/t.js" data-adpop-site="<サイトキー>"></script>
```

- **配信ホストはタグの `src` から読みます。**コードに直書きしていないので、
  ドメインを変えたらタグを貼り替えるだけで移せます。
- ⚠ サイトキーは **HTML に出る公開値**です。秘密ではありません。守っているのは
  **許可ドメイン**(`sites.allowed_origins`)で、**登録していない Origin には設定を返しません**。
- `?adpop_preview=1` を付けると**頻度制御を無視して出ます**。⚠ このときのイベントは**1件も送りません**。

## 動かし方(開発)

前提: Node.js 24 / Docker(ローカルの Supabase 用)

```bash
npm install
cp .env.example .env.local     # ⚠ 値は .env.local にだけ書く(.env* は追跡しない)

# ローカルの Supabase(クラウドのプロジェクトは作りません)
npx supabase start             # ポートは 5452x(他プロダクトのローカルと衝突しない値にしてある)
npx supabase db reset          # supabase/migrations/*.sql を順に適用する

npm run lint
npm run typecheck
npm test                       # ⚠ Docker も Supabase も要らない(PGlite にマイグレーションを流す)
npm run build:embed            # 埋め込みスクリプトを packages/embed/dist と public/embed へ書き出す
npm run check:bundle-size
npm run check:embed-independence

# ローカルの Supabase が起動している間だけ動く(実物の PostgREST に当たる)
npm run check:postgrest
```

⚠ **`npm test` はローカルの Supabase を使いません。** マイグレーションを **PGlite**(WASM の PostgreSQL)へ
通しで流し、**権限と RLS の実効値をその場で測ります**。

🔴 **ただし PGlite 側の「Supabase の既定privilege」は手書きの再現です。**
再現が実物とずれたら、検査は**ずれた前提を測り続けます**。
そのため **CI に実物の Supabase を起動するジョブ**があり、
`anon` キーと `service_role` キーで6表を叩いて **HTTP と SQLSTATE の両方**を突き合わせます
(`npm run check:postgrest`)。⚠ このジョブが見ているのは**未ログインの経路だけ**で、
**ログイン後(authenticated)の経路は実物では1度も通していません**(ログインする画面が PR3 のため)。

同じジョブが**両向き**を測ります:

| 向き | 何を | どこで |
|---|---|---|
| 届かないこと | **どの API キーからも**配信の関数を呼べない | `npm run check:postgrest` |
| **届くこと** | **専用ロールで実際につないで**配信の関数2本を呼べる | `npm run check:delivery-role` |
| 届かないこと | 同じロールで、表・`auth.users`・allow-list の外の関数・関門そのもの・`set role`・`create table`・**一時表**・**スキーマ作成**が**全部 42501** | 同上 |
| 設定が載っていること | `statement_timeout` = 5s / `idle_in_transaction_session_timeout` = 10s | 同上 |

🔴 「届かないこと」だけを測っていると、**配り漏れ(= 配信だけが静かに止まる)**を検出できません。
LP は fail-closed で無傷のままポップが出なくなるので、**誰も気づきません**。

## 外部送信する情報の一覧(電気通信事業法・外部送信規律)

**このタグが外部送信する情報**は次のとおりです(PR2 時点。**そのまま転記できる形**で置いています)。

| 項目 | 内容 |
|---|---|
| **送信先** | タグの `src` に書いた配信ホスト(**自前ホストなら、その運営者自身のサーバー**) |
| **送信される情報** | 匿名ID(`localStorage` 由来の32桁の16進)/ **ページ URL(スキーム + ホスト + パスのみ)** / イベントの種類(発火・抑制・表示・クリック・閉じる)/ トリガ種別 / **端末種別(スマホ・PC の2値)** / 閉じ方(ボタン・背景・Esc)/ 発生時刻 / サイトキー・ポップとバリアントの公開用の識別子 |
| **送信されない情報** | **URL のクエリ文字列とフラグメント**(送る前にも、保存する前にも落とします)/ **IP アドレスの保存** / 生の User-Agent / サードパーティ Cookie / 入力フォームは持っていないので、訪問者が入力した値 |
| 🔴 **送信されうる情報(注意)** | **ページ URL のパスに氏名やメールアドレスが含まれている場合、それは送信されます。** ADPOP が落とすのは**クエリ文字列とフラグメントだけ**で、パスは残します(`/thanks/taro@example.com` のような URL 設計をしている LP では、タグを貼る前に URL を見直してください)。⚠ ただし `user@host` の形(`https://taro@example.com/…`)は**保存を断ります** |
| **利用目的** | ポップの表示制御と効果測定 |
| **送信を止める方法** | タグを外すこと(⚠ オプトアウト UI はありません) |

⚠ 埋め込み先の運営者が規律の対象事業者に当たるかは、その人の事業内容で決まります。
**ADPOP は「対象です / 対象外です」の判定をしません。**

## 自前ホスト

**v1 の時点では手順を用意していません**(PR6)。いまの構成は Next.js + Supabase + Cloudflare R2 です。
⚠ Supabase に強く食い込まない形(RLS と Auth への依存を、後で剥がせる程度に抑える)を実装制約にしています。

## 数字の読み方(先に断っておくこと)

**イベントは埋め込み先のブラウザから送られてくるので、誰でも偽造できます。**
数字は「自分の LP の傾向を見る」用途に限り、**第三者への実績提示には使わないでください**。

## 既知の限界

- **頻度制御は埋め込み先ドメインの `localStorage`** に保存します。
  localStorage が使えない / 消される環境では**抑制が効きません**(Cookie にも第三者にも逃がしません)。
- 訪問者の識別は**匿名IDのみ**。**IP アドレスは保存せず**、User-Agent は「スマホ / PC」の2値に落とします。
  ⚠ **「氏名・メール・電話を送らない」とは言い切れません** —— それらが**ページ URL のパスに
  含まれていれば送信されます**(落とすのはクエリ文字列とフラグメントだけ)。上の表を見てください。
- **オプトアウト UI はありません**(止める方法はタグを外すこと)。
- 🔴 **イベント投入にレート制限がありません**(PR4 以降)。守っているのは `Origin` の照合と
  サイトキーの存在確認、本文 4KB の上限だけです。
- **①戻るトリガは、埋め込み先の履歴を触ります**(`history.pushState` を1枚挟みます)。
  自前で `history` を使う SPA では干渉しえます。⚠ **このトリガだけ個別に OFF にできます**
  (OFF なら `history` に1ミリも触りません)。
- **匿名IDは、`crypto` が使えない環境では `Math.random` で作ります。**暗号的ではありません
  (頻度制御のための識別子で、秘密でも認証でもないため)。
- **端末の2値は `(pointer: coarse)`**、それが無ければ `navigator.maxTouchPoints` で決めます。
  ⚠ どちらも無い古い環境は「PC」と数えます。
- 🔴 **Origin の偽造は防げません。** ブラウザは本物の Origin を送るので、
  「他人が自分の LP にタグを貼った」場合は止まります。**curl に対しては何も守っていません。**
- **①戻るトリガは、出さないと決めたときに `history.back()` で「戻る」を通し直します。**
  ⚠ LP が履歴の最初のページ(直接訪問)なら、その `history.back()` は何も起こしません。
